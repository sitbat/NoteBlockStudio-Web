# MIDI 设备、录制与文件导入

## 连接输入设备

在「MIDI 设备与录制」中点击「授权并刷新设备」后，应用才调用 `navigator.requestMIDIAccess({sysex:false})`。加载页面不会申请设备权限。应用只接收输入消息，不请求 SysEx，也不向外部设备发送演奏或固件数据。浏览器可能显示授权提示；拒绝后可以再次手动连接。Web MIDI 的安全上下文、权限与 SysEx 设置依据 [W3C Web MIDI API](https://www.w3.org/TR/webmidi/#obtaining-access-to-midi-devices)。

浏览器需要提供 Web MIDI API，设备需要被操作系统识别。每个输入设备可独立启停、选择 MIDI 通道、固定音色或使用编辑器当前音色；设备的同号通道拥有各自的弯音、音量、声像、程序及踏板状态。更改通道过滤器会结算不再接收的已按下音符，避免漏掉随后被过滤的 Note Off。

在音色管理器中移动自定义音色时，设备的固定音色引用会一起重排；删除该音色后，设备恢复“当前选择的音色”。“不接收音符”和“当前选择”这两种特殊模式不会被重排。已经按下、尚未松开的被删除音色不会在松键时重新写入废弃的录制编号。

## 实时与步进录制

- 实时录制：按当前播放时钟或开始位置/速度定位，音符起点吸附网格；按住时长按录制速度量化为 duration。
- 步进录制：一组和弦保持相同起点，最后一个音符松开后，光标前进一格。延音踏板仍保持的音符也属于当前和弦。
- 力度与通道音量相乘；CC10 转换为声像；弯音按固定 ±2 半音转换为音分。CC64 在值 64 及以上时启用延音；松开踏板会结算已松键的音符。控制器复位、关闭设备、拔出设备和停止录制会清理相应的录制状态。
- 录制数据包括起点、力度、声像、音分及 duration。NBS 本身不保存 duration；要保留时长信息，使用项目 JSON、完整工程包或 MIDI。

监听和主曲目播放使用分开的 Rust/WASM 音频池。监听会叠加硬件和弦，按 MIDI 通道保存混响，使用当前自定义音色；停止监听不会改变主曲目的播放位置。监听池每个 MIDI 通道最多 64 个同时存在的采样声部，满额会明确拒绝新增声部，不会重置已有和弦。

**监听按音符盒采样的自然长度发声。** Note Off 与延音踏板会改变录制时长，不会把采样延长为持续合成音；松键也不会截断已经发出的采样。弯音在 Note On 时捕获为该音符的音分，之后移动弯音轮不会连续改变已经发声/录制的旧音符。目前不实现 RPN 弯音范围设置、MPE、连续弯音曲线或触后音色调制。录制的 duration 用于数据交换，不改变音符盒采样的自然衰减。

## 导入 MIDI 文件

支持标准 MIDI 格式 0/1、运行状态、PPQN 和 SMPTE 时间。变速文件先转换到实际秒数，再映射到固定的可编辑网格；不添加虚构的 Tempo Changer 乐器。

| 设置 | 行为 |
|---|---|
| 目标速度 | 基础 ticks/s；留空或界面的 0 表示自动 |
| 网格精度 | 界面提供 1 / 2 / 4 / 8 / 16 倍，API 接受整数 1–16；同时放大 tempo 与 tick，保持实际时间，减小起点量化误差 |
| 八度偏移 | 全局 -8…8 八度，在音域检查前应用 |
| 折叠到音符盒音域 | 按八度移入键号 33–57，保留音级 |
| 图层命名 | `track` 使用 MIDI 轨道名，`patch` 使用原版 GM 音色名称，`channel` 使用 MIDI 通道编号 |
| 力度 / 声像 / 使用名称 | 可分别保留；关闭后使用力度 100、声像 0、通用图层名，“使用名称”关闭时不采用所选命名方式 |
| 移除开头空白 | 把第一个保留的音符移到 tick 0；不表示删除零音量音符 |
| 最大图层 | 1–65,535；超限会拒绝整次导入，不截断和弦 |
| GM 音色映射 | 0–127 程序号映射为原生/当前自定义音色，可附加八度偏移，或选择忽略 |
| 打击乐映射 | 按原始 MIDI 鼓键号映射音色及目标 NBS 键号 0–87，或忽略 |
| 每通道覆盖 | 16 个通道分别指定音色和 -8…8 八度，或忽略整条通道；默认沿用音色/鼓键映射 |
| 记住导入设置 | 成功导入并接受替换工程后，记住本次转换选项和三类映射 |

有效速度为基础速度乘精度，保留到 0.01 ticks/s；超过 655.35 ticks/s 或总时间轴超过 1,000,000 tick 时会给出错误。自定义映射必须引用导入设置中已有的定义。导入元数据记录所用设置、有效速度、移除的开头秒数和跳过音符数量。

默认鼓组使用原项目 `midi_instruments.gml` 的 64 项表（MIDI 键 24–87），例如 kick 36 → 音色 2 / NBS 键 39，snare 38 → 3 / 41，closed hi-hat 42 → 3 / 55；表外鼓键使用 click / 键 45。默认旋律自动映射保留本移植版原有行为。源码导出的 `MIDI_PROGRAM_DEFAULTS` 提供全部 128 项原版 GM 音色与八度补偿，可作为 `programMap` 预设传给 `parseMIDI`；例如低音 +2、铃声 -2、长笛 -1 八度。`MIDI_PERCUSSION_DEFAULTS` 提供原版鼓组表。

### 通道映射与优先级

`parseMIDI(bytes, options)` 接受 `channelMap`，键为零起点的 `0…15`，对应 MIDI 通道 `1…16`。值可为 `{instrument, octave}` 或简写的音色编号；`-1` 表示忽略。原生音色编号为 `0…15`，自定义音色从 `16` 开始，必须同时在 `options.customInstruments` 中提供定义。

旋律通道先根据实际 Program Change 选取 `programMap`，再由 `channelMap` 覆盖音色和八度。因此，同一 GM 音色的两个通道可以使用不同采样；通道之后改变 Program，也会保留通道覆盖。覆盖项未写 `octave` 时视为 `0`，不继承被覆盖音色的八度。最后再叠加全局 `octaveOffset`，执行折叠或音域检查。

通道 `9` 是打击乐：先用 `percussionMap` 或原版鼓表求出每鼓绝对键号，再用通道覆盖指定音色并增加八度。通道音色覆盖优先于单鼓音色，包括单鼓的忽略设置；若希望逐鼓筛选，保留该通道的默认覆盖，使用打击乐映射。将 `channelMap[9]` 设为 `-1` 则忽略全部打击乐。

```js
parseMIDI(bytes, {
  programMap: {0: {instrument: 0, octave: 0}},
  channelMap: {
    0: {instrument: 5, octave: -1},
    1: {instrument: 6, octave: 1},
    9: {instrument: 3, octave: 0}
  },
  namingMode: 'channel'
});
```

### 记忆范围

“记住导入设置”使用当前浏览器的 `localStorage` 键 `nbs-midi-import-options-v1`，保存速度、网格、命名、保留标志及 `programMap` / `percussionMap` / `channelMap`。取消导入、解析失败或没有接受替换时，不会覆盖已记忆设置；成功导入时取消勾选会清除旧的记忆内容。导入结果的 `metadata.midiImportOptions` 另记录实际生效设置。

记忆不包含采样音频。再次导入时，自定义音色按完整文件引用（归一化斜线）和根音匹配；没有文件引用时还比较名称。当前工程缺少该定义或存在多个同样身份的定义时，该条映射恢复默认，不把旧编号套到另一种音色。浏览器禁止存储时仍可导入，但不能记住选项。

MIDI 是事件格式，不包含原项目的采样音频或独立混响状态。导出时自定义音色近似为钢琴、打击乐映射为 GM 鼓组；精细采样音色和混响请使用 WAV/音频导出，编辑数据与采样使用完整工程包。

## 已验证范围

纯测试覆盖字节解析、手动授权参数、拒绝权限、实时/步进量化、和弦、延音阈值、控制器复位、弯音边界、设备隔离、通道切换、拔插及停止清理。另有实际随包 WASM 的双音和弦、非零 PCM、独立监听/主曲目时钟和自定义采样回归测试；MIDI 文件导入测试包含真实 65,535 / 65,536 同时音符边界。

本轮 `tests/formats.test.mjs` 增加同 Program 的两个通道分别映射、后续 Program Change、通道 10 与原有鼓键映射的优先级测试。`tests/feature-ui.test.mjs` 用轻量表单适配器调用真实解析器，覆盖 16 行通道设置、成功后记忆、取消不记忆、自定义编号重排、拒绝存储和无效八度；录制回归确认播放时读取 `engine.getTick()` 的歌曲 tick，并按网格量化。这些不等同于浏览器连接物理设备的验收。

**本次没有连接物理 MIDI 键盘、踏板或外部合成器进行端到端测试。** 自动化端口和消息测试证明控制逻辑，不能代替具体硬件、驱动、浏览器权限流程与设备延迟的验证。
