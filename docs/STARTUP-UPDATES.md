# 静态启动与版本更新

v4.4.1 修复两个启动问题：强制刷新后，页面可能绕过已有活动 Service Worker，但旧启动器仍等待不会到来的接管事件；已隔离页面又直接跳过更新，使同一网页可能混用新版 HTML 与旧版脚本。

现在会等待本站 Worker 激活，再按需进行一次普通重载；同一文档中的并发启动合并处理。已运行的编辑器不会因后台消息被自动重载。已有本网站 Worker 会检查更新并接管后，才导入应用。使用原生隔离响应头且没有本站 Worker 的页面不新增注册，其他 Worker 不会被替换或注销。

HTML 的模块入口带固定发布版本。本站脚本、样式及运行时文件采用 HTTP 缓存再验证；导航继续直接取网络。这不是清除站点数据，不删除曲谱、自动备份或模型缓存。跨源模型权重、API、Range 请求和普通音色采样沿用既有策略，不额外重新下载大模型。

正常刷新即可检查更新。Ctrl+F5 触发的未受控文档在本站 Worker 已激活时会进行一次普通重载，不再一直等待 `controllerchange`。若脚本无法激活、网络失败或浏览器策略禁止隔离，仍会显示有限的启动诊断，不反复刷新，也不绕过安全策略。

生命周期说明参考 [web.dev](https://web.dev/articles/service-worker-lifecycle)；本项目行为由启动回归测试及实际浏览器检查分别验证。
