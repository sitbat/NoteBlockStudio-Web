## 硬件、页面与负载

- 本机已确认：AMD Ryzen 9 9950X3D、NVIDIA GeForce RTX 5080、Windows、桌面 Edge 156。原始 JSON 的 UA 为 `Edg/156.0.0.0`，浏览器报告 `hardwareConcurrency=32`。
- 本地静态预览为 `http://127.0.0.1:8792/`，独立 QA 页面为 `/__qa__/`。正式并发记录中页面可见、`isSecureContext=true`、`crossOriginIsolated=true`、AudioContext 为 `running`。
- 本地预览脚本和官方 PyTorch 参考只用于开发验证，生产网站只需静态文件。音频未上传到服务器计算；静态发布目录不包含完整模型权重或开发工作目录。
- 音频输出 48 kHz；14 个音频 Worker，256 帧处理块，目标预读 6 块，即 `6*256/48000=32 ms`。单块约 5.33 ms，实际队列随消费变化，不能把 32 ms 当作完整声学延迟。
- 10,000 条轨道同时持续发声，每轨启用非零混响。报告核验 10,000 份混响状态，共 **138,240,000 字节**；实际最低活跃声部为 10,000。`voicesPerTrack=4` 是容量配置，不能当作实际同时发声数。
- 测量先预热 3 秒，再记录稳定窗口；在约第 15、40 秒修改第 1、10,000 轨混响并插入未来音符，观察真实 Worker 确认与活动声部增加。
- v2 并发输入为上游 `headache_by_lost_deposit_1min.mp3`，文件名虽为 1min，实际解码时长为 72 秒；1,152,977 字节，SHA-256 `63c3cb28a44cafa9f757c2dcc1f3849313e11699a10460a95151033da7c920a3`。浏览器原生 48 kHz 双声道解码，均值混合，由模型 Worker Julius 转 16 kHz；不是预渲染的识别结果。

两组正式单步记录的 `preprocessingRevision=2`，实际 AI 后端为 WebGPU，`activeBatchSize=1`、`activeUnrollSteps=1`。其音频 Worker 池与 AI Worker 分开。`actualCPUThreads=1` 是该 WebGPU 运行时的 WASM 配置读数，不代表 GPU 或整个应用只使用一个执行单元。

## 判定门槛

本轮沿用 QA 的严格条件，不因结果不理想而放宽：

1. 输入按真实 1× 时钟发送：分包调度最大迟到不超过 250 ms，发送完毕的墙钟不超过音频时长加 500 ms。已预加载音频一次性批送不满足该项。
2. **输入结束时**，累计模型块处理 RTF 不超过 1，待处理音频不超过 5.5 秒，没有 backpressure 或推理错误。RTF 是已完成块的处理耗时除以对应音频时长，不包含等待用户录音的全部墙钟。
3. 同时播放窗口最低 10,000 活跃声音、10,000 独立混响状态，输出 RMS 非零，启动与稳态欠载均为 0，最大丢声为 0。
4. 两轮在线混响更改不修改其他轨道参数，未来音符更新有实际确认，并观察到声部增加。

记录 `keptUpAtInputEnd` 反映第 1、2 项，不把 `finish()` 后的排空当作实时继续输入。音符数量和格式有效性也不等于识别准确率，质量另用 GT 测量。

首次实时结果需先收集约 5 秒音频，再加模型计算与调度；本报告的首批墙钟与网页文件批量处理用时、冷启动下载和模型加载时间分别理解。浏览器报告的 `baseLatency` / `outputLatency` 约为 10 / 40 ms，未进行外部声学回环测量。

## 数值缺陷、修复与缓存

旧模板重新生成的 Hann / Mel 数学系数与真实 checkpoint 保存的两个 buffer 不同。相同 Float32 PCM 下，旧网页 Log-Mel 对官方 checkpoint 的最大差为 3.667014，导致首 logits 向量最大差约 0.59426。此差异不能归因于 GPU 普通浮点舍入。

定位时，给同一个官方模型只替换旧网页 Log-Mel，即可复现旧网页首 logits；替换为精确 checkpoint 系数与同一 JavaScript FFT 后，首 logits 对原生最大差降到 `3.05e-5`。输入始终仅 BOS `[1393]`、条件前缀 503，没有强制 tie。small / medium 的 Hann `[2048]`、Mel `[1025,512]` 缓冲区逐字节相同，具体 SHA 及原生诊断见 [模型说明](TRANSCRIPTION-MODELS.md#checkpoint-前处理系数缺陷复核)；局部数学对照为 `benchmarks/local-ai-preprocessing-parity-v1.json`。

本轮真浏览器缓存已升级到 revision 2，使用 `window-v2.f32` / `mel-filter-v2.f32` 的正确 SHA，不重下载完整权重。修正后的 small 同 PCM 首 prefill 1,393 维 logits 对官方原生结果：

| 指标 | 真浏览器结果 |
| --- | ---: |
| 最大绝对误差 | `8.487701416015625e-5` |
| RMSE | `2.2124660924229913e-5` |
| 首 token | 相同，1134 |

原始证据：revision 2 浏览器 probe 为 `benchmarks/local-ai-small-reference-v2.json`，数值比较摘要为 `benchmarks/local-ai-first-logits-parity-v2.json`。这只确认该音频块的首步数值接入，不能替代长序列、跨块 token 或识别质量验收。
