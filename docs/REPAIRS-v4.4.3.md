# v4.4.3 输入、显示与实时音色修复

本版本继续使用纯静态部署，没有新增服务端进程、反向代理配置或推理后端。

## 修复范围

- 资源包导出和数据包导入共用最低限度的 `pack.mcmeta` 校验：拒绝缺失文件、非法 UTF-8 / JSON、非对象根节点或 `pack`、非正安全整数的 `pack_format`。错误说明具体原因；有效的描述组件、附加元数据和资源文件保留。
- `parseNBS` 对自定义音色基准音执行 `0–87` 夹取，与既有正常导入的修复策略相同，不改变有效文件或 NBS 0–5 的往返行为。
- 主播放池在更新事件列表前，按实际引用排队上传首次使用或 PCM 已更换的音色。同一 Worker 同步处理 PCM 上传后才处理后续事件，利用 FIFO 保持顺序，不等待旧的异步确认再发送事件。
- 采样身份按排队版本记录，迟到确认不覆盖新身份。上传失败会报告并停止故障池，停止、换歌或销毁池会取消旧请求。不预装所有未使用音色，也不为新采样重建正在播放的池或清空混响。
- 音色工具栏、完整弹出列表和属性选择框使用固定 DOM 属性与 `textContent` 构建；颜色限于六位十六进制，显示 ID 限于 `0–270`。保留 JSON 扩展字段，不把它们解释为 HTML 或任意 CSS。
- 转录 UI 保留受信的静态模板，新增回归确保模型标签、来源 URL、缓存 ID 和错误文本不会进入 HTML 模板。
- 静态入口通过 meta CSP 限制页面脚本来源、内联事件与 JavaScript eval；仅单独放行 WASM 编译，保留编码和推理所需的受信 Worker。详见[策略范围与 Worker 边界](SECURITY-POLICY.md)。

## 验证

2026-10-26，本地完整回归 **591 项通过，0 失败、0 跳过**，包含独立 scalar WASM 与本地小型模型夹具。

- 畸形资源包及正常原始资源包；NBS 自定义 key `0 / 87 / 88 / 255` 与版本 0–5 往返。
- 真实双 Worker / WASM 的采样上传、事件 FIFO、4 MiB PCM 引起的堆增长、音色替换、确认乱序、停止和池替换；`instrument=270` 的竖琴回退仍可发声。
- 当前 Windows Edge 156、与产品相同的 CSP 下：恶意标签按文字显示，内联事件和 JS `Function` 被阻止，WASM 编译仍正常。
- ONNX Runtime 1.30.0 的两线程 WASM Worker 和 WebGPU Worker 均实际计算通过；GPU 输出在读取前位于 `gpu-buffer`。仅使用微型 Add 图，没有重下完整权重，也没有重做或扩大 AI 识别质量验收。
- 实际浏览器 FFmpeg 导出 MP3、FLAC、AIFF、OGG、WAV 五种格式成功。
- 预载而未使用的自定义音色，在播放中首次加入后实际发声：主池身份不变，8 轨独立混响状态保留，2 Worker，零欠载、零丢声。
- 真实 10,000 轨测试：14 Worker、256 帧、6 块预读，3 秒预热后测量 **60.12745 秒**；最低 10,000 个同时声部，10,000 轨实际独立混响、138,240,000 字节混响状态，启动和稳态欠载均 0，丢声 0。
- 万轨测量期间两次修改不同轨道混响并插入未来音符，实际确认和新增声部均通过。最大事件确认约 7.34 ms、最大混响控制确认约 4.11 ms；这不是外部声学往返延迟。
- 实际编辑器在 1280 像素桌面与 390 像素移动断点均能展开 16 种内置音色并切换选择，移动端无水平溢出，主页面无脚本错误。

详细临时测量只留在本地工作区的 `work/nbs-v443-qa/`；测试页面和夹具不进入发布包。以上性能仅代表本机与所测配置，不扩大到其他设备，也不改变既有 AI 严格实时与识别准确率的未达标结论。
